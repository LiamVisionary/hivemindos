API and storage reference

This page lists the dashboard’s API route groups, the collector and hosted-service endpoints, and where HivemindOS saves state on disk. Use it to find which route owns a workflow or where a piece of data lives.

For the big picture, start with How HivemindOS works.

The dashboard’s local API serves these route groups. They require dashboard auth, except a few routes that check their own credentials, such as signed media links.

Generic runtime routes

These routes work the same way for every runtime. Known runtime ids are openclaw, hermes, aeon, and hivemind-os.

Route Returns

/api/runtimes/[runtime]/skills Installed skills; with an action payload, syncs skills where supported
/api/runtimes/[runtime]/schedules Schedules

/api/runtimes/[runtime]/outputs Outputs
/api/runtimes/[runtime]/integrations Integration status

Crypto routes

These routes help an agent pick and prepare a money rail. They never spend. Sends, trades, crosschain intents, paid API calls, private transfers, card payments, and LLM credit funding still run through the provider’s own route or skill after its spend gate or confirmation.

Route Purpose
/api/crypto/capabilities status reads readiness by provider, select picks a rail for an intent without side effects, and prepare returns a request draft, clear-signing review, and crosschain plan when relevant
/api/crypto/clear-signing Turns an action draft into a clear-signing review with risks, side effects, confirmation text, and fingerprint
/api/crypto/agent-identity Local agent identity records with wallet, ENS/ERC-8004 metadata, endpoints, capabilities, proofs, and status
/api/crypto/risk-monitor Offline risk scoring over wallet policy, identity, env-key presence, endpoints, repo controls, DNS controls, and multisig posture

The router covers Bankr, x402, Veil Cash, MoneyClaw, and UsePod. It reports credentials by key name and status only, never raw values or wallet secrets.

The HivemindOS MCP server exposes the same routes to external agents as crypto_capabilities, select_crypto_rail, prepare_crypto_action, review_crypto_action, agent_crypto_identity, and crypto_risk_monitor. These tools need a running, authenticated dashboard. They are not an offline wallet daemon.

Fleet apps and API services

/api/fleet/apps builds the My Apps launcher from collector reports and service probes across your machines.

  • Browser apps and API-only services are listed separately. Known API services stay usable even when their root page isn’t interactive.
  • /api/fleet/app-icon proxies app icons so browser security doesn’t block them.
  • API services list their routes from an OpenAPI or Swagger document found at a common path such as /openapi.json, /api/openapi.yaml, or /swagger.json. If none exists, a built-in catalog may be used (MiroShark has one).
  • My Apps only offers an open button for safe GET routes without path parameters.

GitLawb Code Proof

GitLawb is optional. If it’s missing, these routes return a safe status instead of breaking setup or the Work board.

Route Purpose
GET /api/gitlawb/status Detect CLI/helper binaries, local DID, node health, repo/peer counts, and MCP availability
POST /api/gitlawb/setup-cli Install or repair lightweight GitLawb CLI binaries where supported
POST /api/gitlawb/identity Create or refresh a local DID without public node registration
POST /api/gitlawb/node/setup Return local-node readiness and guidance
GET /api/projects Read the shared-vault or local-fallback project registry
POST /api/projects Create or update a Hivemind project
POST /api/projects/link-gitlawb Link a project to a GitLawb repo; degrades gracefully when no node is available

Node checks use http://127.0.0.1:7545 by default. Default setup doesn’t host a full node. That only makes sense after you opt into local repo hosting, and it normally means a Docker/Postgres-backed GitLawb node.

Desktop app native commands

The desktop app handles some local actions natively. The browser and remote machines use the API instead.

Command Purpose
desktop_status Build commit, branch, dirty flag, runtime phase, native host, and native server port
list_local_directories Browse folders on this computer without going through the collector
create_local_folder Create a local folder after validating the parent and cleaning the name
display_local_path Show expanded local paths in a readable form

These power local folder picking in AEON workspace linking, chat folders, and the scheduler. Remote machines still go through /api/machines/directories or the collector’s /directories.

Collector endpoints

Every machine in your hive runs a collector. Treat every collector endpoint as private: reachable only over your Tailnet or Hivemind Link.

Endpoint Purpose
GET /health Host, version, env sync status, and capability advertisement
POST /snapshot Local machine, process, runtime, task, and alert snapshot
POST /update Start a HivemindOS update on that machine
GET /env Export known env metadata for a scope or runtime
POST /env Import env values
GET /agents List local runtime agents
POST /agents Create a runtime agent when supported
DELETE /agents Delete a runtime agent when supported
GET /directories Browse folders for machine-targeted workflows
GET /apps Report local apps and services for My Apps
GET /app-proxy/<port>/* Proxy a local app or API service
GET /skills List installed skills from known runtimes
GET /skills/auto-sync Read skill auto-sync settings
POST /skills/auto-sync Configure skill auto-sync

The collector also has endpoints for runtime sessions, chat, schedules, runs, outputs, env sync, and Syncthing.

Where state is stored

Dashboard state

Dashboard preferences and caches are saved by the local server, not in browser storage, so the desktop app and the browser see the same state. Each workspace has its own file:

  • Main workspace: ~/.hivemindos/dashboard-state.json
  • Other workspaces: ~/.hivemindos/workspaces/<id>/dashboard-state.json

This holds agent profiles, shared vault settings, recent tasks, schedules, wallets, chats, folders, discovered machines, and Honey opt-in flags. A new workspace starts clean.

A few install-wide settings always live in the main file and apply to every workspace: terms acceptance, onboarding progress, and appearance such as the theme.

Work you share with other agents belongs in the vault or a runtime, not in dashboard state.

Hosted services

HivemindOS runs these services. Their source is kept outside this app’s repository, and the app talks to the configured endpoint.

Honey ledger

Route Purpose
GET /health Service health
GET /ledger Ledger balance and summary
POST /receipts Signed usage receipt ingestion
POST /observations Lower-trust local usage observations
POST /exchange Honey-to-HIVE ledger exchange; fails closed by default unless a separately authorized hosted conversion policy is enabled
POST /return-to-honey Move legacy ledger-only HIVE back to Honey
POST /claim-bankr-hive Honey-to-HIVE claim; fails closed by default unless a separately authorized hosted conversion policy is enabled
POST /pool-events Admin reward-pool funding events

Legacy reward-pool accounting stays visible for audit and return-to-Honey repair. It is not a current promise of token conversion or a fixed allocation of company revenue.

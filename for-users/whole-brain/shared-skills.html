HivemindOS manual

Shared skills

A skill is a reusable playbook for an agent: a writing style, a research method, a deployment workflow, a media pipeline, or any other repeatable way of working. Hive Superbrain keeps skills in your vault, so every supported agent uses the same instructions without a separate copy per runtime.

Use a shared skill

  1. Open the Skill Browser to see what is installed and browse optional packs.
  2. Install what you need. Optional skills are installed only when you choose them.
  3. Or just ask HivemindOS to find, install, create, or improve a skill for a job.

When a skill applies, the agent reads it before acting. A skill can add steps or safety checks, but it never grants permission to spend money, publish, delete data, or take any other outward action you did not ask for.

To turn a process that worked into a new skill, use Hive Fusion.

What is included

Fresh installs include a small core shelf for engineering work, finding capabilities, shared memory, compiled knowledge, creating workflows, and Obsidian-native files. Bigger or specialized packs stay optional so your shelf does not fill up. See Packaged skills for the full list.

The mobile app includes the same starter skills where they work on a phone. Skills that need desktop software are left out, and some need a connected computer to run. Your edits and removals stay as you left them.

Your existing runtime skills are safe

HivemindOS shows shared skills to each runtime through managed copies. It never overwrites a skill you installed yourself, even if the name matches a shared one.

When an imported plugin skill names a helper file it needs, HivemindOS keeps that helper with the shared skill. Other plugin files stay in the original plugin.

If the shelf shows duplicates or old test skills, run the health tools in Sync and repair.

Where skills live

Skills/README.md
Skills/<slug>/SKILL.md

Agents treat the shared shelf as their first skill source and read Skills/README.md first. Runtime-local skill folders are supplemental overlays for runtime-specific or personal skills.

Runtime projection

Setup copies the shared shelf into each supported runtime’s skill folder as HivemindOS-managed copies, so runtimes that only scan their own folder (such as Codex) still see shared skills.

  • HivemindOS replaces a runtime skill folder only if it carries .hivemind-skill-source.json marking it as HivemindOS-managed.
  • A self-installed skill with the same name is kept and skipped. The shared version stays primary for HivemindOS routing; the local one stays available.
  • Uninstall removes only HivemindOS-managed copies.

HivemindOS can also inventory skills in common Codex, Claude, Hermes, Gemini, OpenClaw, and Aeon locations. Auto-sync settings live outside the vault in ~/.hivemindos/skill-auto-sync.json. Managed copies, including provider-prefixed Aeon mirrors such as aeon-* or claude-*, are never re-imported as new skills, which prevents duplicate loops.

Included by default

The core shelf includes harness-engineering for evidence-based agent improvement experiments, hive-skill-autoresearch for review-gated skill fixes, and engineering-discipline, HivemindOS’ risk-scoped engineering method. For the fuller library, install the HivemindOS Engineering Discipline pack in the Skill Browser; it adds selected obra/superpowers methods and leaves your own colliding skills untouched.

AEON mirror rule

The hidden AEON runtime mirror belongs at:

Operations/Runtime Mirrors/AEON/.aeon

Human AEON profile notes stay under Agents/AEON/<profile>/. The hidden .aeon folder must never become a visible profile folder.

Skill hygiene

Fleet tests create temporary hive-e2e-* skills and must clean them up. When the shelf looks noisy, run the vault doctor. It reports duplicate skills, conflict files, and test leftovers:

pnpm vault:doctor
pnpm vault:doctor -- --fix

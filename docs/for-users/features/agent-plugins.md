# Agent Plugins

HivemindOS can inspect and load local packages that target the published [Agent Plugins 1.0.0 specification](https://agent-plugins.org/specification). A package can contribute portable [Agent Skills](https://agentskills.io/specification), MCP servers, or both.

## Package layout

Choose the package root—the directory containing `plugin.json`:

```text
my-plugin/
├── plugin.json
├── skills/
│   └── summarize/
│       ├── SKILL.md
│       └── references/
└── mcp.json
```

HivemindOS reads only the fixed 1.0.0 locations. It discovers skills from immediate child directories of `skills/` and MCP configuration from root-level `mcp.json`. It uses bundled copies of the official JSON schemas, so inspection does not fetch executable configuration or schemas from the network.

## Inspect and load

1. Open **Skills** from Chat or the Shared Brain.
2. Select **Plugins**.
3. Enter the absolute path to the local package directory.
4. Select **Inspect** to validate the package without importing or starting anything.
5. Review the accepted components and diagnostics.
6. Leave **Import skills** and/or **Connect MCP** enabled, then select **Load plugin**.

Importing a skill audits it with the existing HivemindOS skill security checks, then copies the accepted skill into `Skills/agent-plugins/<plugin-name>/<skill-name>` in the Shared Brain. Reloading a managed skill archives its previous copy before activating the update. A file that already exists at that destination but is not managed by the Agent Plugins loader is left untouched.

MCP loading supports `stdio` and Streamable HTTP. Each valid server is connected independently, so one failed server does not stop valid skills or other servers. Optional legacy HTTP+SSE entries are reported and skipped. **Unload MCP** disconnects the package's live servers; it deliberately preserves imported skills and plugin data.

## Runtime variables and data

For a `stdio` server, HivemindOS provides:

- `PLUGIN_ROOT`: the filesystem-resolved package root.
- `PLUGIN_DATA`: a dedicated writable directory under `~/.hivemindos/agent-plugins/data/`.

The client expands exactly `${PLUGIN_ROOT}` and `${PLUGIN_DATA}` once in `args`, `env` values, and `cwd`. It does not expand the command token, URLs, header names, header values, or unknown placeholders. Plugin data persists across package reloads and MCP unloads. Operators and hermetic tests can select a different base directory with the non-secret `HIVEMINDOS_AGENT_PLUGIN_DATA_ROOT` setting.

Plugin subprocesses receive the MCP SDK's minimal safe platform environment plus values explicitly declared in `mcp.json`; they do not inherit the HivemindOS server's full credential-bearing environment.

## Validation and trust boundary

The loader applies the specification's narrow failure boundaries:

- An invalid `plugin.json` rejects the package before component discovery.
- An invalid fixed component location disables only that component type.
- An invalid skill, MCP entry, or failed MCP connection skips only that entry.
- Unknown manifest fields and unimplemented client extensions are reported and ignored as required by 1.0.0.
- Package paths, resolved symlinks, commands, working directories, and copied skill resources cannot escape the package root or their permitted data root.

Remote MCP URLs must follow the specification's HTTPS rule, except for literal loopback hosts. Cross-origin redirects are not followed automatically, and headers generated by the MCP client take precedence over conflicting package headers.

Inspection establishes format conformance; it does not establish that a package is trustworthy. A local `stdio` server is executable code running with the HivemindOS user's permissions. Load packages only from sources you trust and review their diagnostics first.

## Current lifecycle

Live MCP connections belong to the current HivemindOS server process. Restarting the app disconnects them; load the package again to reconnect. Imported skills and `PLUGIN_DATA` remain available. HivemindOS does not delete plugin data automatically.

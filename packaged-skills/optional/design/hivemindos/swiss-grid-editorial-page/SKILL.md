# Swiss Grid Editorial Page

Build an editorial artifact around a real grid, not decorative alignment.

## Inputs

- Content type, audience, page size or viewport, hierarchy, images/data, and output format.
- Tone: institutional, cultural, technical, manifesto, annual report, exhibit, or product editorial.

## Rules

- Define the grid before designing: columns, gutters, modules, margins, and baseline rhythm.
- Use restrained type hierarchy and flush-left readable text.
- Let white space do real work.
- Use color sparingly and intentionally.
- Avoid fake poster styling that ignores content density, mobile wrapping, or accessibility.

## Workflow

1. Inventory content and hierarchy.
2. Choose a grid system and document it in the artifact or code comments only when helpful.
3. Place content by priority: headline, deck, primary image/data, body, captions, metadata, navigation.
4. Use responsive constraints so text does not overlap or vanish.
5. Verify at mobile and desktop viewports if code is produced.
6. Return grid specs, rationale, and any tradeoffs.

## Capability Map

- Frontend: use existing frontend/design skills and verify screenshots.
- Charts/data: combine with `newsroom-data-visualization` when charts are central.
- Assets: use licensed, supplied, or generated images only with approval.
